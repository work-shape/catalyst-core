- **Connections:** Once a personal Connection has been used in a chat, every later model request in that conversation goes only to a route in `modules.connections.personalModelRegions`. This covers later turns, subagents, siblings whose personal call lands mid-run, and guardrail judges. Before, only the run that made the call was checked. A subagent's routes now include its parent's, so an `eu` subagent under a parent on another region is refused the personal call with `personal_connection_region`. A run start or queued message that names a blocked model, or falls back to one, is refused with `personal_data_model_region` before the run is created. A request refused mid-run ends the run with that code. A blocked judge answers "could not be evaluated", so a blocking guardrail stops the call. Configured models carry `personalDataBlocked` when their route is outside the list. In such a conversation the model picker shows them disabled with "Not allowed in a conversation with data from personal connections" / "Nicht für Unterhaltungen mit Daten aus persönlichen Verbindungen freigegeben" and preselects the first allowed model. When none is allowed, the composer points to "New conversation" / "Neue Unterhaltung". Workflow runs, conversations without personal data and instances whose routes are all in the list are unchanged. There is no new setting, right, migration or audit event.
