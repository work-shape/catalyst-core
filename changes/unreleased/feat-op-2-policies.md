section: Added

- **Settings > Instance > Policies:** An admin who holds the new instance right `policy.manage` (admins hold it by default) sees every operation of the instance in plain words: whether it reads or changes, whether a change can be undone, and whether it runs, asks first, needs an approval or is off, with where that comes from. The admin sets a central setting per operation or per pattern such as `connection.crm.*`, optionally narrowed to a Shared Workspace and an asset kind, and locks "Always allow" per operation or pattern. Settings hold from the next call, wherever the operation is called; where several match, the strictest wins. Locks of the release config (`policy.alwaysAllow.locked`) are listed and cannot be lifted on the screen or through the API (`FORBIDDEN`, reason `locked_by_release`). The operations are `policies.get`, `policies.set` and `policies.set_always_allow_lock`. Each change is audited as `governance.policy_setting_changed` or `governance.always_allow_lock_changed` with the operation, its narrowing and the old and new value only.
- **Outside hosts in a draft:** The admin's switch is now the policy of `apps.allow_draft_host` on Settings > Instance > Policies, off (`deny`) by default. The release config key `apps.draftHosts` is removed: a config that still holds it is refused with a message that says where the switch moved. An instance that had it on sets `apps.allow_draft_host` to "Runs" once after the upgrade.
