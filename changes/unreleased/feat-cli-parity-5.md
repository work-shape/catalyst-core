- **CLI:** Commands for the person's own account and their Shared Workspaces: `catalyst me`, `me update`, `me model-preference`, `me set-model-preference`, `keys revoke <key-id>`, `workspace list|directory|show|create|update|deletion-impact|delete`, `workspace members [candidates|add|role|remove|leave]` and `workspace requests [ask|approve|decline]`. Each calls the existing operation the screens use (`me.*`, `me.api_keys.revoke`, `workspaces.*`). `workspace delete` needs `--confirm-name`, as the screen does. See the CLI reference ("Account and workspace commands").
- **Personal API keys:** A key's new account and workspaces level, ticked by hand on a new key in Settings > API keys and never in advance. The page that confirms a connect code (`catalyst setup`, `catalyst login`) offers neither this level nor the instance level. A superadmin's key acts on their own workspace memberships only, never as Owner of every Shared Workspace. `account.manage` lets the key change the person's name, language, follow-up mode and model preference and revoke their keys; it is never limited to a workspace. `collaboration_workspace.manage` lets it manage the person's Shared Workspaces, their members and access requests, through the same role checks as the Members screen; limited to a workspace, it reaches that workspace only and neither lists nor creates workspaces. They carry the new operation scopes `account:manage` and `workspaces:manage`, which only these operations accept from a key; `me:write` and `collaboration_workspace:*` stay off every key. A key still issues no key, changes no password and deletes no account. Revoking a key and every workspace change made through a key are audited as on the screen, with the key that made them.
