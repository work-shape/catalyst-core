section: Fixed
---

- **Personal connections:** A personal MCP server made in the New connection dialog no longer fails at its test. The dialog saves it without a test, asks the person for their own sign-in, and then reads its tools with that sign-in. A personal REST API is saved without a test as well.
- **Personal connections (CS-9b exception):** `connections.discover` on a personal MCP Connection runs the MCP handshake and `tools/list` with its owner's own binding, never a tool call, only for the owner (`ownerPrincipalId`) signed in to the instance in a first-party session, with no delegated actor, no API key and no Workflow, App, agent or schedule as origin. Anyone else is refused with `personal_connection_context` before anything is queued. It runs as the job kind `connection.discover_personal`, which carries the owner as `personalOwner`, checks it again against the Connection's revision, keeps the automatic attempts of any discovery and is refused by `instance.jobs.retry` (`kind_not_retried`). A `connection.discover` job of a personal Connection contacts nothing and is not retried. Saving a personal Connection, setting its client secret and a start of the instance queue no discovery of it. A failed owner's discovery leaves the Connection's shared health, error code and tools as they were. The discovery marks no conversation; its `connection.discovered` and `connection.discovery_failed` events carry counts or the reason and `personal: true` only. Only the owner sees the tools the discovery read in `connections.get`, until the owner accepts tools: those become the Connection's declared operations, which its readers see as any declared operation, and each call still needs the caller's own sign-in in an allowed chat. Its test stays refused.
