- **Knowledge Bases, origin link:** The builder enters, changes or clears where the original of a document added by hand lives, on the Knowledge Base page or through `knowledge_bases.set_origin_link` (`POST /api/v1/knowledge-bases/:knowledgeBase/documents/origin-link`, `knowledge_base.write`). A synced or Workflow-fed document keeps the link its source gives it and is refused with `409` `knowledge_origin_link_synced`. A link is an `http` or `https` address of at most 4,000 characters without a user, a password or a token parameter (such as `token`, `sig` or `X-Amz-Signature`); anything else is refused, and a connector's link that is not such an address is dropped while its file is kept. `knowledge_bases.list_documents` now answers each document's `originLink`, so only readers of the Knowledge Base see it, as in search passages. Every change is audited as `knowledge_base.origin_link_changed` with the document id and `set` or `cleared`, never the link. A citation offers the stored copy at its page and the original, which opens in a tab that cannot reach back into the page.
- **Knowledge Bases, declared filters:** A Knowledge Base on the built-in backend declares `filters`, each with a `name`, a `type` (`string` or `date`), a `description`, the document `field` it narrows (`title`, `file_name`, `document_type`, `source`, `path`, `added_at` or `modified_at`) and an optional comparison `op` (`eq` and `prefix` for text, `eq`, `gt`, `gte`, `lt` and `lte` for dates). `knowledge_bases.search` and the agent tool `knowledge.search` take `filters` by name; every value is bound as a parameter, a filter the Knowledge Base does not declare is refused, and the agent tool skips a Knowledge Base that does not declare a filter it is given, with the reason `filter_not_declared`. The generated tool description lists each Knowledge Base's filters. Filters on a Knowledge Base of tables and filters on extracted fields are refused.
