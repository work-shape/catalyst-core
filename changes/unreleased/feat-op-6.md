- A person's own confirmation settings (OP-6): per operation Always allow, Ask me or Never, for the calls their own agents make, chat and scheduled runs alike. A confirmation card in chat and a confirmation in the Inbox offer "Always allow" only where it would let the next call run; a floor, a guardrail, an approval or an admin's lock keeps asking. Never refuses the call before it runs and keeps the tool from the agent. Settings are listed and changed under Settings > You > Confirmations through `me.operation_settings.list` and `me.operation_settings.set`, by the person in their own session only, never with a personal API key, an embedding host's token or for a delegated actor; each change is audited as `user.operation_setting_changed` with the operation and the value alone. Always allow reaches only runs the person started in their own first-party session, their scheduled starts and subagents of those; a run started with a key or for a delegated actor still asks, while Ask me and Never apply to it too. Workflow calls and other people's calls are never affected.
- Release config `policy.alwaysAllow.locked` names operations exactly, or every operation under a prefix such as `connection.crm.*`, for which nobody may set Always allow. A malformed entry (`*`, `name*`) fails config load, and one that names no operation of the instance fails startup. Only reversible operations permit it at all; irreversible, outward and undeclared ones never do.
